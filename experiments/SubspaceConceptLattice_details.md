# SubspaceConceptLattice

## Overview
- SubspaceConceptLattice (SCL) learns compositional, hierarchical visual representations grounded in Formal Concept Analysis (FCA).
- Each concept is a tuple of (attribute subspace, object subspace), where subspaces are represented via ridge projector matrices.
- The concept lattice emerges from subspace intersection (attributes) and union (objects) operations, enforced by structural losses.
- Unlike MemorySubspaceLattice, SCL has no discrete memory bank — the concept encoder directly produces continuous basis vectors that define the subspaces. This makes optimization smoother but introduces the challenge of degenerate equilibria.

## Architecture

### Processing Pipeline
1. **Perceptual Encoder** (ViT): Maps images to patch-level embeddings `(B, num_patches, embed_dim)`.
2. **Concept Encoder** (MLP + MHA): Takes perceptual embeddings and produces:
   - `X_attr`: Attribute basis vectors `(B, n_attr, ambient_dim)` — these span the attribute subspace.
   - `X_obj`: Object basis vectors `(B, n_obj, ambient_dim)` — these span the object subspace.
   - Both are converted to projector matrices via ridge regression: `P = X^T(XX^T + λI)^{-1}X`.
3. **Decoder** (ViT): Reconstructs images from attribute projector matrices (singleton concepts only).

### Key Parameters
- `ambient_dim`: Dimensionality of the subspace embedding space. Each subspace lives in R^{ambient_dim}.
- `n_attr`: Number of attribute slots (basis vectors per concept's attribute subspace). Each slot captures one factor of variation.
- `n_obj`: Number of object basis vectors per concept.
- `lbd`: Ridge regularization parameter (default 0.05). Makes projectors non-idempotent (P^2 ≠ P), which is important for IC MSE.
- `attr_force_orthogonal_basis`: When true, each slot's basis vector is masked to only occupy its designated dimensions (slot 0 → dims [0, dims_per_slot], slot 1 → next dims, etc.). Ensures within-concept orthogonality by construction.
- `intersection_power_steps`: Number of matrix power iterations for computing subspace intersection (default 5). Higher = sharper intersection but harder optimization.

### Subspace Operations
- **Intersection** (attributes): Average projectors of constituents, then raise to a power: `P_inter = (mean(P_i))^k`. Converges to the shared subspace as k → ∞.
- **Union** (objects): Concatenate basis vectors of constituents, then compute ridge projector of the concatenation.
- **Inclusion**: `incl(A ⊆ B) = Tr(P_A @ P_B) / Tr(P_A)`. Measures what fraction of A's subspace is contained in B.
- **Ridge Projector**: `P = X^T(XX^T + λI)^{-1}X`. Custom backward pass for numerical stability (`_StableRidgeProjectorFn`).

## Required Conditions

### 1. Attribute Rank Ordering (Inverse Cardinality)
The attribute subspace rank should decrease as concept cardinality increases, reflecting that larger groups of objects share fewer common attributes.

| Concept | Cardinality | Expected Attr Rank | Reasoning |
|---------|------------|-------------------|-----------|
| Any singleton (e.g., red circle) | 1 | 2.0 | Has both attributes (color + shape) |
| Same-color pair (e.g., red circle + red square) | 2 | 1.0 | Share 1 attribute (color) |
| Same-shape pair (e.g., red circle + blue circle) | 2 | 1.0 | Share 1 attribute (shape) |
| Cross pair (e.g., red circle + blue square) | 2 | 0.0 | Share 0 attributes |
| All 4 objects | 4 | 0.0 | No common attributes |

With n_attr=2, attr ranks range from 0 to 2. Sub-1.0 values are NOT pathological — they reflect genuine attribute sparsity.

### 2. Object Rank Ordering (Proportional Cardinality)
The object subspace rank should increase with concept cardinality, reflecting that larger groups contain more distinct objects.

| Concept | Cardinality | Expected Obj Rank | Reasoning |
|---------|------------|------------------|-----------|
| Any singleton | 1 | 1.0 | Single object |
| Any pair | 2 | 2.0 | Two distinct objects |
| Any triple | 3 | 3.0 | Three distinct objects |
| All 4 objects | 4 | 4.0 | Four distinct objects (= n_obj) |

### 3. Galois Connection
The attribute and object subspaces must respect the Galois duality from FCA:
- **Attr direction**: A combined concept's attribute subspace must be included in each constituent singleton's attribute subspace. `incl(P_attr_combined ⊆ P_attr_singleton) ≈ 1.0` for all valid constituent singletons.
- **Obj direction**: Each constituent singleton's object subspace must be included in the combined concept's object subspace. `incl(P_obj_singleton ⊆ P_obj_combined) ≈ 1.0`.

### 4. Intersection Consistency (IC)
For any combined concept, its attribute subspace should match the intersection of its constituents' attribute subspaces:
- `P_attr_combined ≈ intersect(P_attr_singleton_1, P_attr_singleton_2, ...)`
- **IC MSE** (preferred): `MSE(P_attr_combined, P_intersection) → 0`. This provides per-slot gradient pressure.
- IC Bounds (deprecated): `incl(P_combined ⊆ P_intersection) → 1`. This is a weaker constraint that allows degenerate solutions.

### 5. Union Consistency (UC)
For any combined concept, its object subspace should match the union of its constituents' object subspaces:
- `P_obj_combined ≈ union(P_obj_singleton_1, P_obj_singleton_2, ...)`

### 6. Factorized Attribute Representation
Each attribute slot should encode exactly one factor of variation. With the v0 dataset (color + shape):
- **Slot 0**: Should encode one attribute (e.g., color). Same-color concepts should have |cos_sim| ≈ 1 in this slot; different-color concepts should have |cos_sim| ≈ 0.
- **Slot 1**: Should encode the other attribute (e.g., shape). Same-shape concepts aligned; different-shape concepts orthogonal.
- The model should discover this factorization without supervision — we don't prescribe which slot gets which attribute.

**Diagnostic**: The per-slot pairwise cosine similarity matrix should show a clean block-diagonal pattern (checkerboard), NOT uniform similarity.

### 7. Reconstruction Quality
Singleton concepts must reconstruct their source images faithfully. Reconstruction loss should converge to a low value (typically < 0.05 for v0 dataset). This ensures the learned subspaces actually contain the visual information.

### 8. Attr-Obj Orthogonality
The attribute and object subspaces should be orthogonal (non-overlapping), so they capture complementary information:
- `Tr(P_obj @ W @ P_attr @ W^T) ≈ 0` (with learnable orthogonal transform W).

### 9. Singleton Object Distinctness
Each singleton's object subspace should be distinct from others, collectively spanning n_obj dimensions. The pairwise inclusion between singleton obj subspaces should be polarized toward {0, 1} — some objects share features (high inclusion), others are distinct (low inclusion).

## Loss Functions

### Core Losses (should almost always be active)
| Loss | Purpose | Target |
|------|---------|--------|
| `reconstruction_loss` | Visual fidelity | MSE between input and decoded image → 0 |
| `galois_attr_loss` | Attr Galois connection | incl(combined_attr ⊆ singleton_attr) → 1 |
| `galois_obj_loss` | Obj Galois connection | incl(singleton_obj ⊆ combined_obj) → 1 |
| `intersection_consistency_loss` | IC (use MSE mode) | P_combined ≈ P_intersection |
| `union_consistency_loss` | UC | P_combined ≈ P_union |
| `singleton_obj_rank_loss` | Obj rank anchor | Singleton obj rank → 1 |
| `max_singleton_attr_rank_loss` | Attr rank anchor | Singleton attr rank → n_attr |

### Structural Losses
| Loss | Purpose | Notes |
|------|---------|-------|
| `basis_orthogonality_loss` | Per-slot structure | Modes: `rank` (per-slot collective rank to target), `ortho` (push all cos_sim→0, flawed but strong destabilizer), `polarize` (push |cos_sim| to {0,1}), `balance` (entropy on mean |cos_sim|), `balance_sharp` ((p−0.5)² quadratic penalty). Config: `balance_weight` (multiplier for balance/balance_sharp, default 1.0), `basis_ortho_anneal_epochs: [start, end]` (linear interpolation ortho→polarize). |
| `obj_subspace_orthogonality_loss` | Obj subspace structure | Use `polarize` mode. Rank component pushes collective rank to n_obj. Polarize pushes inclusion to {0,1} with balance entropy. |
| `attr_obj_orthogonality_loss` | Attr-obj separation | Use `direct` mode. Minimizes Tr(P_obj @ W @ P_attr @ W^T). |
| `cross_slot_decorrelation_loss` | Slot independence | Minimizes cross-covariance between slots. Prevents both slots encoding the same factor. |
| `attr_sink_loss` | High-cardinality rank reduction | Constrains combined attr subspaces relative to bottom element. Needs sufficient ambient_dim. |

### Proportionality Losses
| Loss | Purpose |
|------|---------|
| `loss_attr_card_inv_prop` | Attr rank inversely proportional to cardinality |
| `loss_obj_card_prop` | Obj rank proportional to cardinality |
| `loss_attr_obj_inv_prop` | Attr and obj ranks inversely related |

### Other Losses
| Loss | Purpose |
|------|---------|
| `repulsion_loss_attr` / `repulsion_loss_obj` | Push singleton subspaces apart (soft) |
| `attr_polarization_loss` | Push inclusion values toward 0 or 1 |
| `galois_cycle_loss` | Cycle consistency through the Galois connection |
| `basis_sparsity_loss` | L1 on basis norms toward 1.0 |
| `rank_conservation_loss` | Penalize rank loss in projector vs basis |

## Key Findings from Experiments

### IC MSE vs IC Bounds (exp_125 vs exp_126)
- **IC MSE is strictly required** for attribute rank differentiation. MSE creates per-slot gradient asymmetry via element-wise projector matching. Bounds only cares about scalar inclusion, providing no per-slot differentiation pressure.
- With IC MSE: attr ranks show correct inverse ordering (card_1=2.0, card_2=1.07, card_4=0.52, card_8=0.12).
- With IC Bounds: all attr ranks stuck at ~2.0 (degenerate equilibrium).
- Analysis: `analysis/comparisons/scl_exp_125_126/ANALYSIS_REPORT.md`

### Degenerate Equilibria
- All lattice-theoretic losses (Galois, IC bounds, UC) have global minima at uniform subspaces (all concepts identical). This is the primary enemy.
- IC MSE breaks this via the amplification mechanism: reconstruction noise → slight singleton differences → asymmetric intersection eigenvalues → MSE forces combined concepts to match asymmetry → backprop amplifies differences → factorized representation.

### The Ortho Paradox (exp_127/129/130)
- The "ortho" mode is conceptually WRONG (pushes same-attribute concepts apart) but functionally ESSENTIAL for breaking the degenerate equilibrium.
- The "polarize+balance" replacement is conceptually CORRECT but CANNOT escape degeneracy: polarize has ZERO gradient at the degenerate fixed point (all cos_sim=1), and balance provides 6× weaker gradient than ortho.
- Ortho's value is as a **destabilizing force**, not as a target. IC MSE then steers the destabilized representation toward correct factorization.
- Analysis: `analysis/comparisons/scl_exp_127_129_130/ANALYSIS_REPORT.md`
- **Current approaches** (exp_131–134): Keep ortho+corrections, amplify balance 50×, sharp (p−0.5)² penalty, ortho→polarize anneal. See `experiments/scl_exp_131_134.md`.

### Ambient Dim and Slot Structure
- With `attr_force_orthogonal_basis=True`, each slot gets `ambient_dim / n_attr` dimensions.
- `ambient_dim=4, n_attr=2` → 2 dims per slot. Tight but functional.
- `ambient_dim=8, n_attr=2` → 4 dims per slot. Richer per-slot representations, better for attr_sink_loss.

## Configuration Reference

### Recommended Baseline Config (as of exp_127+)
```yaml
model:
  config:
    ambient_dim: 4           # or 8 for richer representations
    n_attr: 2
    n_obj: 4
    lbd: 0.05
    intersection_power_steps: 5
    attr_force_orthogonal_basis: true
    ic_mode: "mse"           # REQUIRED for attr differentiation
    uc_mode: "bounds"
    attr_obj_orthogonality_direct: true
    obj_subspace_orthogonality_mode: "polarize"
    basis_orthogonality_loss_type:
      - rank
      - polarize
      - balance
    concept_encoder:
      config:
        mapping_type: mlp     # strictly superior to linear
        encoder_depth: 2
        clamp_X: false        # true destroys continuous learning
    loss_weights:
      reconstruction_loss: 1.0
      galois_attr_loss: 1.0
      galois_obj_loss: 1.0
      intersection_consistency_loss: 1.0
      union_consistency_loss: 1.0
      singleton_obj_rank_loss: 1.0
      max_singleton_attr_rank_loss: 1.0
      basis_orthogonality_loss: 1.0
      obj_subspace_orthogonality_loss: 1.0
      attr_obj_orthogonality_loss: 1.0
      cross_slot_decorrelation_loss: 1.0
      attr_sink_loss: 1.0
```
